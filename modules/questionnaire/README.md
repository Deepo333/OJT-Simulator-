# `modules/questionnaire` — Stage 2, Step 2

Owner of the questionnaire step. All 15 questions are generated by Claude
(`lib/ai/generate-questionnaire.ts`) under one governing principle:

> The résumé and profile are the candidate's true current level; generate
> every question from there. The target job is only the destination we
> measure distance to — it decides *what* to measure, never *how* to phrase.

That yields questions a far-gap candidate can answer honestly from their
own experience ("When you had to learn your store's POS system, how did
you go about it?") while a candidate with relevant experience gets more
advanced phrasing. Résumé claims are verified, not assumed; job-description
tools are never named as if used; traits (learning style, work style,
pressure, confidence, unfamiliar situations) are measured through
transferable experience.

Composition: 5 questions about how the candidate learns and works
(`LEARNING_STYLE` / `WORK_STYLE`) and 10 skill probes (`VERIFY_CLAIMED` /
`PROBE_JOB_REQUIREMENT`, each with an internal `targetSkill` label in the
destination's terms).

Answer format is chosen from the shape of each question, not a quota:
`MULTI_SELECT` when a person could honestly resonate with more than one
option, `SINGLE_SELECT` when options are mutually exclusive (and written so
exactly one fits). The server appends **"None of these"** to every
multi-select question; choosing it clears other choices and reveals an
optional elaboration box. There is no generic "other / explain" option.

## Files

- `types.ts` — client-facing question + answer shapes.
- `actions.ts` — Server Actions:
  - `ensureQuestionnaire(jobListingId)` — idempotent generator called on
    page load; assigns stable ids and option values, adds "None of these".
  - `submitQuestionnaire(...)` — writes `QuestionnaireResponse` rows
    (`selectedOptions[]` + optional free text), then runs Step 3
    (assessment) and Step 4 (curriculum) and returns the curriculum URL.

The DB rows are the contract for Step 3.
